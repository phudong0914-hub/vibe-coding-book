🚀 Sổ tay Vibe Coding Thực Chiến

Thời gian đọc: 10 phút · Playbook Chuẩn Senior Engineer

📍 Quy Trình Vibe Coding 7 Bước: Từ Ý Tưởng Đến Sản Phẩm Có Thể Ship

Playbook này giúp bạn dùng AI coding agents như Codex, Claude Code, Cursor hoặc các agent tương tự một cách có kỷ luật hơn: vẫn giữ tốc độ vibe coding, nhưng có ngữ cảnh sạch, kế hoạch rõ, giao diện tốt, code dễ sửa, kiểm thử được và giảm rủi ro trước khi triển khai.

Công thức tổng quát: Reference → Context sạch → Product Spec → Implementation Plan → Design System → Build từng milestone → Verify/Refactor → Security Audit → Ship.

💡 Vì Sao Cần Một Quy Trình Vibe Coding?

Vibe coding rất mạnh khi bạn muốn biến ý tưởng thành sản phẩm nhanh. Bạn có thể đưa cho AI một URL mẫu, ảnh giao diện, tài liệu yêu cầu hoặc mô tả ngắn, rồi để AI đọc code, tạo file, chạy thử và tự sửa lỗi. Tuy nhiên, nếu thiếu quy trình, AI rất dễ tạo ra sản phẩm "trông có vẻ đúng" nhưng sai mục tiêu, giao diện chung chung, code khó bảo trì hoặc không sẵn sàng để ship.

Quy trình dưới đây không nhằm làm bạn chậm lại. Ngược lại, nó tạo một đường ray rõ ràng để AI chạy nhanh hơn, đúng hơn và ít bị lạc hướng hơn. Bạn vẫn giữ vai trò quan trọng nhất: người định hướng sản phẩm, người duyệt chất lượng và người quyết định gu thẩm mỹ cuối cùng.

🎯 Nguyên Tắc Cốt Lõi

  1. 1. Context trước, code sau: AI chỉ làm tốt khi nó nhìn thấy đúng ngữ cảnh. Trước khi yêu cầu code, hãy đưa cho AI tài liệu yêu cầu, reference, ảnh chụp, constraint kỹ thuật và tiêu chí hoàn thành.
  2. 2. Milestone nhỏ tốt hơn làm tất cả một lần: Đừng yêu cầu AI làm toàn bộ app trong một lượt. Hãy chia thành các mốc nhỏ có thể chạy được: layout trước, state sau, API sau nữa, rồi mới polish animation và responsive.
  3. 3. Design system trước khi polish UI: Nếu không có bộ quy tắc về màu, font, spacing, radius, shadow, component state và motion, AI thường tạo giao diện an toàn nhưng nhạt. Design system giúp giao diện nhất quán ngay từ đầu.
  4. 4. Verify bằng bằng chứng, không chỉ bằng cảm giác: Sau mỗi vòng build, cần kiểm tra bằng build log, test, trình duyệt, ảnh chụp màn hình, responsive, console error và các trạng thái loading/empty/error.

🚀 Quy Trình 7 Bước Vibe Coding Chuẩn Thực Chiến

Bước 0: Chọn Đúng Kiểu Dự Án

Trước khi bắt đầu, hãy xác định bạn đang làm loại dự án nào. Mỗi loại cần workflow, skill và tiêu chí kiểm tra khác nhau:

  • Clone/recreate website mẫu: cần phân tích reference, chụp toàn trang, ghi lại animation và tái tạo giao diện bằng code mới.
  • Làm app/tool từ ý tưởng: cần product spec, luồng sử dụng, state, form, dữ liệu và trạng thái lỗi.
  • Làm SaaS/dashboard: cần information architecture, bảng dữ liệu, filter, chart, empty state và permission flow nếu có.
  • Làm game/3D/animation: cần gameplay loop, performance, input handling, camera, collision, state và test tương tác.
  • Sửa/refactor repo có sẵn: cần đọc kiến trúc hiện tại, giới hạn phạm vi sửa và giữ nguyên behavior.

Bước 1: Chuẩn Bị Ngữ Cảnh Sạch

Mục tiêu của bước này là biến mọi nguồn đầu vào thành tài liệu rõ ràng để AI đọc được: website mẫu, PDF, ảnh chụp, video quay màn hình, ghi chú sản phẩm hoặc repo hiện có.

Cấu trúc gợi ý:

/context/spec.md
/context/reference.md
/context/screenshots/
/context/constraints.md

Công cụ nên dùng:

  • Firecrawl: chuyển website hoặc tài liệu online thành Markdown phù hợp cho LLM.
  • Crawl4AI: crawler mã nguồn mở tối ưu cho AI/RAG pipeline.
  • OpenDataLoader PDF: bóc tách PDF, bảng, cột và tài liệu phức tạp thành dữ liệu dễ đọc.
  • Full-page screenshot hoặc screen recording: dùng khi cần clone/recreate giao diện và animation.

💬 Prompt mẫu:

Đọc toàn bộ context. Tóm tắt:
1. Mục tiêu sản phẩm
2. Người dùng chính
3. Tính năng bắt buộc
4. Style/UI reference
5. Rủi ro kỹ thuật
6. Phần còn thiếu cần hỏi lại

Chưa code ở bước này.

Bước 2: Viết Product Spec

Tạo file PRODUCT_SPEC.md để khóa mục tiêu sản phẩm trước khi code. Đây là bước giúp AI không làm lệch ý tưởng ban đầu.

Nội dung tối thiểu:

  • Người dùng là ai?
  • Họ cần giải quyết vấn đề gì?
  • Luồng sử dụng chính là gì?
  • Tính năng MVP gồm những gì?
  • Tính năng nào tạm bỏ qua ở phiên bản đầu?
  • Tiêu chí nào được xem là hoàn thành?

💬 Prompt mẫu:

Dựa trên context đã có, hãy tạo PRODUCT_SPEC.md.
Spec cần ngắn gọn, rõ ràng, có MVP scope và tiêu chí hoàn thành.
Nếu thiếu thông tin quan trọng, hãy liệt kê câu hỏi trước khi code.

Bước 3: Lập Implementation Plan

Tạo file IMPLEMENTATION_PLAN.md để chia dự án thành các milestone nhỏ có thể kiểm tra được.

Cấu trúc nên có: Tech stack, Cấu trúc thư mục, Component/module chính, Data model, API hoặc local state, Test plan, Milestone build, Rủi ro và cách kiểm tra.

💬 Prompt mẫu:

Bạn là Senior Lead Engineer.
Dựa trên PRODUCT_SPEC.md, hãy lập IMPLEMENTATION_PLAN.md.
Chia thành milestone nhỏ, mỗi milestone phải có output rõ ràng và cách verify.
Chưa code cho đến khi plan đủ rõ.

Bước 4: Tạo Design System Trước Khi Dựng UI

Đây là bước quyết định giao diện có chuyên nghiệp hay không. Trước khi AI tạo nhiều component, hãy yêu cầu nó tạo bộ design system: màu sắc, font, khoảng cách, radius, shadow, state, responsive và motion.

Nội dung nên có trong DESIGN_SYSTEM.md: Color tokens, Typography scale, Spacing scale, Border radius, Shadow/elevation, Button/input/card states, Responsive rules, Motion rules.

Skill nên dùng từ MengTo/Skills:

  • web-design/landing-page: khi làm landing page hoặc trang giới thiệu sản phẩm.
  • web-design/pricing-page: khi làm trang giá, bảng so sánh gói và FAQ.
  • web-design/tailwindcss: khi muốn UI gọn, responsive và dễ bảo trì bằng Tailwind.
  • web-design/build-awwwards-quality-sites: khi muốn giao diện giàu cảm xúc, cao cấp hơn template thông thường.
  • web-design/gsap hoặc animation-on-scroll: khi cần motion có chủ đích.

💬 Prompt mẫu:

Áp dụng tinh thần MengTo/Skills cho UI/web-design.
Tạo DESIGN_SYSTEM.md và CSS tokens gồm: màu chủ đạo & phụ, typography scale, spacing scale, radius, shadow, button/input/card states, responsive & motion rules.
Tránh UI xám mặc định. Ưu tiên hierarchy rõ, đọc dễ, đẹp và dùng được.

Bước 5: Build Theo Milestone Nhỏ

Đây là phần vibe coding thật sự. Hãy để AI code nhanh, nhưng theo từng mốc rõ ràng. Mỗi milestone phải chạy được trước khi sang mốc tiếp theo.

  • Milestone 1: layout chính, navigation, mock data.
  • Milestone 2: form, filter, search hoặc interaction chính.
  • Milestone 3: state, API hoặc data persistence.
  • Milestone 4: responsive polish, empty state, loading state, error state.
  • Milestone 5: animation, hover state, micro-interaction và final polish.

💬 Prompt mẫu:

Hoàn thành Milestone 1 theo IMPLEMENTATION_PLAN.md.
Sau khi code xong, hãy chạy app, kiểm tra lỗi runtime và ghi lại những gì đã hoàn thành.
Không mở rộng ngoài scope của milestone này.

Bước 6: Verify, Review Và Refactor

Khi code bắt đầu lớn, đừng đợi đến cuối mới dọn. Nếu một file vượt khoảng 300-500 dòng hoặc một component làm quá nhiều việc, hãy yêu cầu AI refactor thành module nhỏ hơn nhưng giữ nguyên behavior.

Checklist verify: Build production thành công, không lỗi runtime/console error quan trọng, desktop/mobile không vỡ layout, text không tràn/chồng, loading/empty/error state rõ ràng, component gọn gàng.

💬 Prompt mẫu:

Review code theo vai trò senior reviewer.
Tìm bug, duplication, component quá lớn, state khó hiểu và rủi ro maintainability.
Đề xuất refactor nhỏ, giữ nguyên behavior và giao diện hiện tại.

Bước 7: Security Audit Và Ship

Không nên nói sản phẩm "an toàn 100%". Cách nói đúng hơn là: audit để giảm rủi ro trước khi public. Tập trung vào secret leak, XSS, auth, dependency, unsafe API usage và lỗi build production.

Checklist security trước khi ship: Không commit API key/token/.env, validate user input, không render unsafe HTML, không gọi private API trực tiếp từ FE, check lỗ hổng dependency, build production thành công.

💬 Prompt mẫu:

Audit security trước khi ship.
Tập trung vào secret leak, XSS, auth, dependency, unsafe API usage và lỗi production build.
Phân loại P0/P1/P2. Sửa P0 và P1 trước.

🎨 Cách Áp Dụng MengTo/Skills Hiệu Quả

MengTo/Skills là thư viện skill dạng Markdown cho AI coding agents. Cách dùng đúng nhất không phải là nhồi toàn bộ repo vào context, mà là chọn đúng skill hẹp nhất cho việc hiện tại, đưa file SKILL.md tương ứng vào context, rồi yêu cầu AI làm theo.

Khi clone hoặc recreate website mẫu:

  • codex/stitched-full-page-capture: chụp toàn bộ trang để AI không chỉ thấy phần hero.
  • codex/video-to-superprompt: biến video scroll hoặc animation thành prompt chi tiết.
  • codex/html-to-interaction-prompts: tách HTML, section, hover và interaction thành prompt nhỏ.
  • web-design/landing-page: dựng lại landing page có cấu trúc và visual hierarchy rõ.
  • codex/audit-verify-explain-grade-5: audit kết quả, chấm điểm và ưu tiên lỗi cần sửa.

Khi làm giao diện web/app hiện đại:

  • web-design/tailwindcss: giữ component gọn, responsive và dễ chỉnh.
  • web-design/gsap: dùng khi animation phức tạp cần kiểm soát timeline.
  • web-design/animation-on-scroll: dùng khi cần hiệu ứng xuất hiện theo cuộn trang.
  • web-design/threejs: dùng khi có 3D hoặc WebGL.
  • web-design/pricing-page: dùng cho SaaS pricing, comparison, FAQ và CTA.

⚡ Công thức dùng skill:

1. Chọn đúng skill → 2. Đọc SKILL.md → 3. Tạo spec ngắn cho task hiện tại → 4. Build milestone nhỏ → 5. Kiểm tra bằng browser/test → 6. Audit kết quả → 7. Polish có kiểm soát.

✅ 7. Checklist Trước Khi Ship

Danh sách kiểm tra bắt buộc phải rà soát qua 4 góc độ trước khi triển khai công khai:

📦 Product

  • Luồng chính dùng được từ đầu tới cuối.
  • CTA, form, navigation và trạng thái lỗi rõ ràng.
  • Không còn placeholder gây hiểu nhầm.

🎨 UI/UX

  • Desktop và mobile không vỡ layout.
  • Text không tràn, không chồng lên nhau.
  • Motion có ích, không làm trang nặng.

💻 Code

  • Build production thành công.
  • Component lớn đã được tách hợp lý.
  • Không có console error quan trọng.

🔒 Security

  • Không leak API key hoặc file .env.
  • Input được validate.
  • Không render HTML user nhập một cách unsafe.

⚠️ Lỗi Thường Gặp Khi Vibe Coding

  • ❌ Bắt đầu bằng "làm app này cho tôi" nhưng không có spec.
  • ❌ Nhồi quá nhiều context khiến AI lạc ở giữa hoặc dùng nhầm thông tin.
  • ❌ Yêu cầu AI làm toàn bộ dự án một lần, sau đó rất khó debug.
  • ❌ Không tạo design system nên giao diện nhìn giống template mặc định.
  • ❌ Không kiểm tra bằng trình duyệt thật, chỉ tin vào câu trả lời của AI.
  • ❌ Đợi đến cuối mới refactor, khiến code phình to và khó sửa.
  • ❌ Nói "an toàn 100%" thay vì audit rủi ro cụ thể.

📌 Kết Luận

Vibe coding hiệu quả không phải là để AI làm mọi thứ một phát rồi hy vọng kết quả đúng. Cách làm tốt hơn là để AI chạy nhanh trong một quy trình rõ ràng: context sạch, spec rõ, plan nhỏ, design system tốt, build từng milestone, verify liên tục, refactor đúng lúc và audit trước khi ship.

Khi đó, bạn không chỉ "chat với AI để code", mà đang vận hành một quy trình sản xuất phần mềm nhẹ, nhanh và có khả năng lặp lại. AI là người tăng tốc. Bạn là người giữ mục tiêu, chất lượng và gu sản phẩm.
