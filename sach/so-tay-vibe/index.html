1. Tổng Quan & Nguyên Tắc Cốt Lõi

Playbook này giúp bạn dùng AI coding agents như Codex, Claude Code, Cursor hoặc các agent tương tự một cách có kỷ luật hơn: vẫn giữ tốc độ vibe coding, nhưng có ngữ cảnh sạch, kế hoạch rõ, giao diện tốt, code dễ sửa, kiểm thử được và giảm rủi ro trước khi triển khai.

Công thức tổng quát: Reference → Context sạch → Product Spec → Implementation Plan → Design System → Build từng milestone → Verify/Refactor → Security Audit → Ship.

💡 Vì Sao Cần Một Quy Trình Vibe Coding?

Vibe coding rất mạnh khi bạn muốn biến ý tưởng thành sản phẩm nhanh. Bạn có thể đưa cho AI một URL mẫu, ảnh giao diện, tài liệu yêu cầu hoặc mô tả ngắn, rồi để AI đọc code, tạo file, chạy thử và tự sửa lỗi. Tuy nhiên, nếu thiếu quy trình, AI rất dễ tạo ra sản phẩm "trông có vẻ đúng" nhưng sai mục tiêu, giao diện chung chung, code khó bảo trì hoặc không sẵn sàng để ship.

Quy trình dưới đây tạo một đường ray rõ ràng để AI chạy nhanh hơn, đúng hơn và ít bị lạc hướng hơn. Bạn giữ vai trò quan trọng nhất: người định hướng sản phẩm, người duyệt chất lượng và người quyết định gu thẩm mỹ cuối cùng.

🎯 4 Nguyên Tắc Cốt Lõi

  1. 1. Context trước, code sau: AI chỉ làm tốt khi nhìn thấy đúng ngữ cảnh. Đưa cho AI tài liệu yêu cầu, reference, ảnh chụp, constraint kỹ thuật và tiêu chí hoàn thành trước khi gõ dòng code nào.
  2. 2. Milestone nhỏ tốt hơn làm tất cả một lần: Đừng yêu cầu AI làm toàn bộ app trong một lượt. Chia thành các mốc nhỏ có thể chạy được: layout trước, state sau, API sau nữa, rồi mới polish animation và responsive.
  3. 3. Design system trước khi polish UI: Định nghĩa bộ quy tắc màu, font, spacing, radius, shadow, state và motion trước để giao diện nhất quán và chuyên nghiệp ngay từ đầu.
  4. 4. Verify bằng bằng chứng, không chỉ cảm giác: Sau mỗi vòng build, kiểm tra lại bằng build log, test tự động, trình duyệt thật, ảnh chụp màn hình, responsive, console error và các trạng thái loading/empty/error.

2. Quy Trình Vibe Coding 7 Bước Chuẩn Senior

Bước 0: Chọn Đúng Kiểu Dự Án

Trước khi bắt đầu, xác định loại dự án để áp dụng workflow và tiêu chí kiểm tra phù hợp:

  • Clone/recreate website mẫu: Phân tích reference, chụp toàn trang, ghi lại animation và tái tạo bằng code mới.
  • Làm app/tool từ ý tưởng: Xác định product spec, luồng sử dụng, state, form, dữ liệu và trạng thái lỗi.
  • Làm SaaS/dashboard: Thiết kế information architecture, bảng dữ liệu, filter, chart, empty state và permission flow.
  • Làm game/3D/animation: Xây dựng gameplay loop, performance, input handling, camera, collision và test tương tác.
  • Sửa/refactor repo có sẵn: Đọc kiến trúc hiện tại, giới hạn phạm vi sửa và giữ nguyên behavior cũ.

Bước 1: Chuẩn Bị Ngữ Cảnh Sạch (Context Ingestion)

Biến mọi nguồn đầu vào thành tài liệu rõ ràng để AI đọc được: website mẫu, PDF, ảnh chụp, video quay màn hình, ghi chú hoặc repo hiện có.

Cấu trúc thư mục gợi ý:

/context/spec.md
/context/reference.md
/context/screenshots/
/context/constraints.md

Công cụ khuyến nghị: Firecrawl (crawl web ra Markdown), Crawl4AI (crawler RAG), OpenDataLoader PDF (bóc tách PDF/bảng biểu), Full-page screenshot.

Bước 2: Viết Product Spec & Agent Governance

Tạo file PRODUCT_SPEC.md để khóa mục tiêu sản phẩm và thiết lập kỷ luật không cho AI code bừa bãi.

Nội dung tối thiểu: Người dùng chính, Vấn đề cần giải quyết, Luồng sử dụng chính, Tính năng MVP, Phần bỏ qua ở v1, Tiêu chí hoàn thành.

Bước 3: Lập Implementation Plan

Tạo file IMPLEMENTATION_PLAN.md theo góc nhìn Senior Engineer để chia nhỏ dự án thành các mốc kiểm tra được.

Cấu trúc plan: Tech stack, Cấu trúc thư mục, Module chính, Data model, Local state/API, Test plan, Milestones, Rủi ro.

Bước 4: Tạo Design System Trước Khi Dựng UI

Quyết định tính thẩm mỹ chuyên nghiệp ngay từ đầu trước khi sinh nhiều component. Yêu cầu AI tạo DESIGN_SYSTEM.md và file CSS Tokens.

Nội dung Design System: Color tokens (HSL/Dark mode), Typography scale, Spacing scale, Radius, Shadow, Form/Button states, Responsive & Motion rules.

Bước 5: Build Theo Milestone Nhỏ

Thực hiện vibe coding theo từng mốc nhỏ. Mỗi milestone phải chạy kiểm thử thành công trước khi chuyển sang mốc tiếp theo.

  • Milestone 1: Layout chính, navigation, mock data.
  • Milestone 2: Form, filter, search hoặc tương tác chính.
  • Milestone 3: State management, API integration, data persistence.
  • Milestone 4: Responsive polish, empty/loading/error states.
  • Milestone 5: Micro-interactions, animation & final visual polish.

Bước 6: Verify, Review Và Refactor

Kiểm tra lại toàn bộ sản phẩm bằng chứng cứ (Build production, Console log, Layout mobile/desktop). Khi file vượt 300-500 dòng, yêu cầu AI tách thành các module độc lập nhưng giữ nguyên hành vi.

Bước 7: Security Audit Và Ship

Rà soát an ninh mạng trước khi triển khai công khai. Phân loại lỗi theo P0/P1/P2 và xử lý triệt để P0/P1 (Leak API key, XSS, Unsafe Input, Build error).

6. Prompt Mẫu Chi Tiết Có Thể Copy

Bộ Prompt Mẫu chi tiết nguyên văn dành cho AI Coding Agent trong từng giai đoạn:

🔥 Master Prompt Cho Dự Án Mới

Tôi muốn làm dự án này theo quy trình vibe coding senior.

Hãy làm theo thứ tự:
1. Đọc context/reference.
2. Tạo PRODUCT_SPEC.md.
3. Tạo IMPLEMENTATION_PLAN.md theo milestone nhỏ.
4. Tạo DESIGN_SYSTEM.md dựa trên MengTo/Skills phù hợp.
5. Build từng milestone, mỗi milestone phải chạy được.
6. Sau mỗi milestone, verify bằng build/test/browser.
7. Khi code phình to, refactor module nhỏ.
8. Trước khi ship, audit security và UX.

Không làm quá rộng. Ưu tiên bản chạy được, đẹp, dễ sửa, rồi polish dần.

📄 Prompt Tạo Spec

Đọc toàn bộ context. Tóm tắt:
1. Mục tiêu sản phẩm
2. User chính
3. Tính năng bắt buộc
4. Style/UI reference
5. Rủi ro kỹ thuật
6. Phần còn thiếu cần hỏi lại

Sau đó tạo PRODUCT_SPEC.md. Chưa code.

🗺️ Prompt Tạo Plan

Bạn là Senior Lead Engineer.
Dựa trên PRODUCT_SPEC.md, lập IMPLEMENTATION_PLAN.md.
Chia thành milestone nhỏ có thể chạy được.
Mỗi milestone cần có output, file chính cần sửa, cách verify và rủi ro.
Chưa code cho đến khi plan rõ.

🎨 Prompt Tạo Design System

Áp dụng tinh thần MengTo/Skills cho UI/web-design.
Tạo DESIGN_SYSTEM.md và CSS tokens gồm:
- màu chủ đạo và màu phụ
- typography scale
- spacing scale
- radius
- shadow
- button/input/card states
- responsive rules
- motion rules

Tránh UI xám mặc định. Ưu tiên hierarchy rõ, đọc dễ, đẹp và dùng được.

🛡️ Prompt Audit Trước Khi Ship

Audit dự án trước khi ship.
Tập trung vào:
- lỗi runtime/build
- responsive và text overlap
- accessibility cơ bản
- duplicate code và component quá lớn
- secret leak
- XSS hoặc unsafe user input
- dependency/security risk

Phân loại P0/P1/P2. Sửa P0 và P1 trước.

7. Checklist Kiểm Tra Trước Khi Ship

Bảng kiểm tra 4 khía cạnh tiêu chuẩn sản phẩm trước khi đưa ra người dùng thật:

📦 Product

  • Luồng chính dùng được từ đầu tới cuối.
  • CTA, form, navigation và trạng thái lỗi rõ ràng.
  • Không còn placeholder gây hiểu nhầm.

🎨 UI/UX

  • Desktop và mobile không vỡ layout.
  • Text không tràn, không chồng lên nhau.
  • Motion có ích, không làm trang nặng.

💻 Code

  • Build production thành công.
  • Component lớn đã được tách hợp lý.
  • Không có console error quan trọng.

🔒 Security

  • Không leak API key hoặc file .env.
  • Input được validate.
  • Không render HTML user nhập một cách unsafe.

Những bẫy phổ biến làm dự án vibe coding bị thất bại hoặc mất thời gian debug:

  • ❌ Bắt đầu bằng "làm app này cho tôi": Không có spec khiến AI tự suy đoán tính năng sai lệch.
  • ❌ Nhồi quá nhiều context rối: Làm AI bị nhiễu thông tin ở giữa hoặc nhầm lẫn giữa các phiên bản.
  • ❌ Yêu cầu làm toàn bộ dự án 1 lần: Code sinh ra quá lớn, vỡ logic và cực kỳ khó tìm vết để fix.
  • ❌ Bỏ qua Design System: Giao diện sinh ra mang cảm giác mờ nhạt, xám xịt như template mặc định.
  • ❌ Chỉ tin lời nói của AI mà không chạy thử: AI báo "đã fix lỗi" nhưng thực tế build bị crash.
  • ❌ Đợi cuối dự án mới refactor: Code phình to trên 1000 dòng khiến việc chia tách bị vỡ behavior.
  • ❌ Tuyên bố "an toàn 100%": Không thực hiện audit lỗ hổng thực tế trước khi push public.

9. Kết Luận & Định Hướng Vận Hành

Vibe coding hiệu quả không phải là để AI làm mọi thứ một phát rồi hy vọng kết quả đúng. Cách làm tốt hơn là để AI chạy nhanh trong một quy trình rõ ràng: context sạch, spec rõ, plan nhỏ, design system tốt, build từng milestone, verify liên tục, refactor đúng lúc và audit trước khi ship.

Khi đó, bạn không chỉ "chat với AI để code", mà đang vận hành một quy trình sản xuất phần mềm nhẹ, nhanh và có khả năng lặp lại. AI là người tăng tốc. Bạn là người giữ mục tiêu, chất lượng và gu sản phẩm.
